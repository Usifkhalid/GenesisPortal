# Security checklist

Session 27 (2026-10-13). A line-by-line review of the hand-written session store and CSRF check
against OWASP guidance (Session Management, CSRF Prevention, Authentication and Secure Headers
cheat sheets; ASVS 4.0 chapters 3, 4, 12 and 14), followed by the rest of the application.

Status words: **Fixed** (changed this session, with a test), **OK** (reviewed, already right),
**Accepted** (a known limit, with the reason), **Open** (not done; needs something this project
does not have yet).

Nothing here has run in Azure: there is no subscription or tenant access yet. Everything marked
Fixed or OK is proven by `npm test` on this machine; the Azure-only parts are marked Open.

## 1. Sessions (`backend/src/lib/session.js`, `middleware/auth.js`, `modules/auth/`)

| #   | Check                                           | Status   | Notes                                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | Session fixation: new id at sign-in             | OK       | `startSession` regenerates before the user id is stored; the old id stops being a session and the pre-sign-in CSRF token dies with it. Test: "signing in replaces the session id and the CSRF token".                                                                                              |
| S2  | New id on a change of privilege                 | Fixed    | Roles were already read fresh on every request, but the session id survived a role change. Now the session records a privilege key (company + roles); when it changes the session is destroyed and the person signs in again (one redirect with Entra). D126.                                      |
| S3  | Helpdesk team membership change                 | Accepted | Agent/Lead is a team membership, not a role: it is read on every ticket request, so a removal applies at once, but it does not end the session. The membership grants no access outside the ticket service.                                                                                        |
| S4  | Idle timeout enforced on the server             | OK       | 8 h (`SESSION_IDLE_MINUTES`). The row's `expiresAt` is checked on every read; an expired row is deleted, whatever the cookie says.                                                                                                                                                                 |
| S5  | Absolute lifetime                               | Fixed    | There was none: an active session lived for ever. Now 12 h from sign-in (`SESSION_ABSOLUTE_HOURS`), enforced on the server on every request; the cookie is also capped to what is left. A signed-in session with no start time is ended. D127.                                                     |
| S6  | Cookie flags                                    | OK       | `HttpOnly`, `SameSite=Lax`, `Path=/`; in production `Secure` and the `__Host-` prefix (no Domain, bound to the exact origin). Lax, not Strict, because Entra returns the browser by a cross-site top-level GET.                                                                                    |
| S7  | Session id strength                             | OK       | express-session's 24 random bytes (192 bits), signed with HMAC-SHA256. The cookie holds the id and nothing else.                                                                                                                                                                                   |
| S8  | Secret strength and rotation                    | Fixed    | Production now needs 32+ characters and refuses a placeholder. `SESSION_SECRET_PREVIOUS` lets a rotation happen without signing everyone out.                                                                                                                                                      |
| S9  | Sign-out destroys the session on the server     | OK       | Row deleted, cookie cleared with the attributes it was set with, Entra session ended too. Never refused (D111).                                                                                                                                                                                    |
| S10 | Deactivated person or company                   | OK       | Checked on every request; the session is destroyed. The Entra callback now also refuses a person whose company is inactive (it used to be caught one request later).                                                                                                                               |
| S11 | Expired rows removed                            | OK       | Hourly job, now under a lease so one instance does it.                                                                                                                                                                                                                                             |
| S12 | Session data                                    | OK       | User id, start time, privilege key, CSRF token and (during an Entra sign-in only) the state, nonce and PKCE verifier, deleted on first use. No token from Entra is ever stored.                                                                                                                    |
| S13 | Responses that carry session data are not cached | OK       | `Cache-Control: no-store` on everything under `/api` and `/auth`.                                                                                                                                                                                                                                  |
| S14 | Anonymous sessions                              | Accepted | `GET /api/auth/config` creates a session row for the CSRF token before sign-in. A flood of them is capped by the `/api` rate limit and removed by the hourly prune.                                                                                                                                |
| S15 | Concurrent sessions per person                  | Accepted | Not limited (HQ desktop plus phone is normal). `Session.userId` is indexed, so "sign this person out everywhere" is one delete if it is ever needed.                                                                                                                                               |
| S16 | A missing `NODE_ENV` on Azure                   | Fixed    | It would have meant development: mock sign-in, open to the internet. The config loader now refuses to start on App Service (`WEBSITE_SITE_NAME` present) unless `NODE_ENV=production`.                                                                                                             |

## 2. CSRF (`backend/src/middleware/csrf.js`)

| #   | Check                                    | Status   | Notes                                                                                                                                                                                                              |
| --- | ---------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| C1  | Pattern                                  | OK       | Synchroniser token: 32 random bytes per session, sent back in `X-CSRF-Token`. A custom header also forces a CORS preflight, which is never answered.                                                               |
| C2  | Every state-changing method is covered   | OK       | Everything but GET, HEAD and OPTIONS, on every route under `/api` and `/auth`, sign-in included (no login CSRF). No GET route changes state (reviewed with the matrix).                                            |
| C3  | Token comparison                         | OK       | `crypto.timingSafeEqual` after a length check. The Entra `state` and `nonce` use the same.                                                                                                                         |
| C4  | Token lifetime                           | OK       | Bound to the session: replaced at sign-in, gone at sign-out and at either timeout.                                                                                                                                 |
| C5  | Defence in depth: where the request came from | Fixed    | New: a write that the browser marks `Sec-Fetch-Site: cross-site` or `same-site` is refused before the token is looked at. Browsers without the header are judged on the token alone.                               |
| C6  | Sign-out without a token                 | Accepted | Deliberate (D111): a stale tab must be able to sign out. The worst a forged request can do is sign someone out, and `SameSite=Lax` already keeps the cookie off cross-site POSTs.                                  |
| C7  | Token exposure                           | OK       | Returned only in same-origin JSON (`/api/auth/config`, `/api/me`), never in a URL, never logged (redacted).                                                                                                        |

## 3. Sign-in and rate limiting

| #   | Check                                   | Status   | Notes                                                                                                                                                                                                                                                       |
| --- | --------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | The real client address behind Azure    | Fixed    | `trust proxy` is the number of proxies (`TRUST_PROXY_HOPS`, 1 for App Service), so only the address Azure itself appended is used and a forged `X-Forwarded-For` is ignored. App Service writes `ip:port`; the port is removed, or no two requests would ever share a key. IPv6 is counted by /56. |
| R2  | One office, one public address          | Fixed    | The old cap (20 sign-ins per 15 min per address) would have locked out HQ. Now: 10 per account (`AUTH_ACCOUNT_RATE_LIMIT_MAX`) and 600 per address (`AUTH_RATE_LIMIT_MAX`), both per 15 min. D128.                                                         |
| R3  | Counters with two instances             | Accepted | In memory per process: with two instances the effective caps are at most double. Passwords are checked by Entra (with its own lockout), not here, so the caps protect capacity, not credentials.                                                            |
| R4  | Entra flow                              | OK       | Authorization code + PKCE (S256), `state` and `nonce` single-use and compared in constant time, tenant checked twice, redirect URI built from `APP_BASE_URL` never from the Host header, fixed error reasons on the way back (no open redirect).            |
| R5  | Mock sign-in                            | OK       | Answers only when `AUTH_MODE=mock` and `NODE_ENV=development`; production refuses to start with it (and now also with mock Graph).                                                                                                                         |
| R6  | Entra against the real tenant           | Open     | Never run: tenant access has not been granted.                                                                                                                                                                                                              |

## 4. Headers, CSP, CORS

| #   | Check                     | Status   | Notes                                                                                                                                                                                                                                                                   |
| --- | ------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | Content-Security-Policy   | Fixed    | Was `style-src 'self' 'unsafe-inline'` on top of helmet's defaults. Now written out in full: `default-src 'none'`; scripts, styles, fonts, connections, manifest and worker `'self'`; images `'self' data: blob:`; no inline script or style, no `unsafe-eval`, no other origin. The 76 `style="…"` attributes in the frontend became `data-css` values applied through the CSS object model (`html.js`). Files under `/assets` carry a one-line policy (`default-src 'none'; frame-ancestors 'none'`) to keep header bytes off phones. Outside production only, same-origin frames are allowed for the mocked-mail preview, which is served with its own sandboxed policy. D129. |
| H2  | Clickjacking              | OK       | `frame-ancestors 'none'` and `X-Frame-Options: DENY`.                                                                                                                                                                                                                   |
| H3  | HSTS                      | Fixed    | Production: one year, `includeSubDomains`. It followed the process's `NODE_ENV` rather than the app's configuration; now the configuration.                                                                                                                              |
| H4  | Other headers             | Fixed    | `nosniff`, `Referrer-Policy: no-referrer`, COOP and CORP `same-origin`; `Permissions-Policy` added (camera, microphone, geolocation, payment, USB and sensors all off); `X-Powered-By` removed.                                                                         |
| H5  | CORS                      | OK       | Closed: no `Access-Control-*` header is ever sent and preflights are not answered. Tested.                                                                                                                                                                              |
| H6  | User files                | OK       | Attachments are always a download with `Content-Security-Policy: default-src 'none'; sandbox`; images are served with the type their own signature gave.                                                                                                                |
| H7  | Trusted Types             | Accepted | Not enabled: pages build markup as strings through one `esc()` function, which Trusted Types would need rewritten as a policy.                                                                                                                                          |
